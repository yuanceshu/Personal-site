Read when：新增实验作品、改变作品归属、调整实验服务共享边界，或判断是否需要新 App/Service。

Do not read when：修改现有作品内部的 UI、文案、Schema 或业务逻辑。

Source of truth：本文档负责实验作品的组织与接入边界；单个作品行为以对应项目规格和代码为准。

## 作品、应用与服务

- AI 场景诊断工作台、UI 实验室和行业 Demo 集是主站平级作品入口。
- 行业 Demo 集内部包含岛见和食智助手等子作品；行业标签不等于新 App。
- 主站前端统一位于 `apps/main`。只有独立导航、依赖、部署、受众或隐私边界成立时才拆 App。
- 动态实验可以复用 `services/experiment-agents`，但每个作品拥有自己的路由、Schema、提示词、业务模块和测试。
- 静眠森继续使用独立 App 与专属服务，不参与实验服务复用。

## 服务与契约边界

- 实验服务使用 FastAPI/Pydantic；前端按作品使用 Zod 或现有类型做运行时校验。
- Pydantic/Schema 是服务接口权威；合法 JSON 仍需通过业务语义检查。
- 模型只承担已定义的理解或生成步骤。订单、金额、库存、模板渲染和状态机等确定性业务留在明确代码中。
- 不建立全站 contracts 包、账号体系、通用 Agent 平台或共享业务数据库，除非多个已上线作品出现相同的真实需求。
- 外部既有 H5 可以保持独立边界；接入主站只建立入口，不复制客户代码、数据、品牌、报价或凭据。

## 新实验接入

新增作品时依次确认：它是否已有主站位置；是否需要真实服务端；状态是否跨请求保存；是否可复用实验服务；接口和权限如何隔离；部署与费用限制如何验证。只建立当前实现需要的目录、依赖和资源。

本地验收不代表公开部署。真实模型、限流、外部资源和 Production 状态写入对应项目规格或部署记录。
