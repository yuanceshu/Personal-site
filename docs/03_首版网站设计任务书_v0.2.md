# 首版网站设计任务书 v0.2

状态：首版基线（第二版优化见 [`05_第二版网站优化说明.md`](05_第二版网站优化说明.md)）  
更新时间：2026-08-20

## 1. 本次修订

MVP 不使用灵眠、静眠森、梦境入口或现实映像等设定，也不使用深色首页。

首版只做一件事：

> 用最短路径让访客理解袁策书是谁、擅长做什么，以及目前有哪些值得点进去看的作品。

世界观资料继续保留，但不在首版留下角色占位、隐藏彩蛋、叙事文案或未来入口。

## 2. 首版目标

访客应当：

- 在 10 秒内知道这是袁策书的个人作品站；
- 理解创作者擅长理解复杂问题、做出取舍并把想法变成真实体验；
- 无需选择浏览模式，一次点击进入 Project 000；
- 在 60 秒内完成“需求 + 场景 + 约束”体验；
- 看完作品后形成判断：“他不是讲了一门课，而是把课程当作产品设计了。”

## 3. 目标访客

- 认识作者、希望了解其真实能力的同事、朋友与合作伙伴；
- 关注 AI、产品、体验设计和创造过程的行业访客；
- 偶然收到 Project 000 独立链接的普通访客。

首页不要求访客先理解作者的完整履历，也不使用模糊的个人品牌口号代替真实作品。

## 4. 设计原则

### 4.1 先信息，后气质

页面先说清楚姓名、定位和作品，再通过排版、留白、色彩与细节形成个性。

### 4.2 作品是首页的主体

首版只有一个作品，因此不伪装成作品很多的列表、筛选器或分类体系。Project 000 使用一个足够完整的大入口。

### 4.3 明亮但不轻飘

首页使用暖白、纸白和少量清晰蓝色。避免纯白科技官网、糖果色卡片、渐变光晕和大面积玻璃拟态。

### 4.4 真实内容优先

首页最主要的视觉不是抽象装饰或人物插画，而是 Project 000 的真实课堂照片和明确问题。

## 5. 首版信息架构

```text
首页 /
├── 姓名与一句话定位
├── 当前创作方向
├── Project 000 精选作品入口
└── 极简关于信息

Project 000 /works/project-000
├── 返回首页
├── 封面与核心问题
├── 60 秒互动
├── 用户问题
├── 研发与协作
├── 210 分钟取舍
├── 体验设计
├── 四地迭代
├── 证据、不足与反思
└── 返回首页
```

首页页头中的“作品”和“关于”是区段锚点，不为内容不足的栏目建立独立路由。

## 6. 首页结构

### 6.1 桌面端

```text
┌──────────────────────────────────────────────────────────┐
│ 袁策书 / 作品与学习记录                    作品    认识我 │
├──────────────────────────────────────────────────────────┤
│                                                          │
│  袁策书                                                  │
│  把复杂的问题，重新设计成                               │
│  真实的人愿意使用的体验。                               │
│                                                          │
│  AI、产品与一些值得被做出来的实验。                     │
│                                                          │
│  理解问题      做出取舍      设计体验                    │
│                                                          │
├──────────────────────────────────────────────────────────┤
│ SELECTED WORK / 001                                      │
│                                                          │
│ [真实课堂远景]       把一门 AI 培训课，当成产品来设计   │
│                      如何让普通员工在 3.5 小时后         │
│                      真的愿意开始使用 AI？               │
│                      4 城 · 339 人 · 约 160 小时         │
│                      [查看项目 →]                        │
└──────────────────────────────────────────────────────────┘
```

首屏应同时露出精选作品入口的标题或图片上边缘，避免让访客先经过一整屏空泛自我介绍。

### 6.2 移动端

顺序为：

1. 姓名与极简导航；
2. 一句话定位；
3. 创作方向；
4. 真实课堂主图；
5. Project 000 标题、核心问题和事实；
6. 查看项目；
7. 极简关于信息。

移动端不缩小桌面双栏，而是让作品图片和文字自然上下排列。

### 6.3 首页暂定文案

姓名：

> 袁策书

主陈述：

> 把复杂的问题，重新设计成真实的人愿意使用的体验。

补充：

> AI、产品与一些值得被做出来的实验。

能力标签使用普通词：

> 理解问题 · 做出取舍 · 设计体验

这些是工作文案，不视为最终个人定位。正式实现前可以继续校准，但页面结构不依赖某个固定句式。

## 7. 首页视觉方向

### 7.1 色彩

- 页面底色：温暖的浅灰白，不使用纯白或深色大底；
- 内容表面：纸白，用于精选作品图片和局部内容区；
- 主文字：带暖度的炭黑；
- 次级文字：中性灰；
- 强调色：清晰、低饱和的蓝色，用于链接、编号和少量重点；
- 辅助色：非常浅的米色，用于区分项目页的纪录片段落。

颜色承担信息层级，不把每个区块染成不同颜色。

### 7.2 排版

- 姓名、导航、正文和按钮使用清晰现代的中文黑体；
- 首页主陈述和 Project 000 大标题可使用有书卷感、但不过分古典的中文宋体；
- 英文只用作小型编号或眉题；
- 不使用超细字重、全大写长句或大量斜体营造高级感；
- 首页通过字号、留白和网格建立气质，不依赖装饰插画。

### 7.3 图像

- 首页直接使用 Project 000 的真实课堂远景；
- 图片保持自然比例和现场感，不裁成只剩讲师个人；
- 可以使用一条蓝色标注线或极小编号连接图片与项目信息；
- 首版不生成抽象 AI 插画作为首页主视觉。

## 8. Project 000 封面

### 8.1 桌面端

```text
┌──────────────────────────────────────────────────────────┐
│ 袁策书 / 作品                              ← 返回首页    │
├──────────────────────────────────────────────────────────┤
│ PROJECT 000 · AI TRAINING AS A PRODUCT                   │
│                                                          │
│ 把一门 AI 培训课，         [山西课堂远景主图]            │
│ 当成产品来设计                                           │
│                                                          │
│ 如何让一群几乎不懂 AI 的普通员工，                       │
│ 在 3.5 小时后真的愿意开始使用 AI？                       │
│                                                          │
│ 4 座城市    339 名学员    约 160 小时    210 分钟        │
│                                                          │
│ ↓ 先花 60 秒，体验最重要的一个差别                       │
└──────────────────────────────────────────────────────────┘
```

### 8.2 移动端

- 返回入口清楚但不抢标题；
- 眉题、标题、核心问题、主图和数字采用单列；
- 数字像展览说明，不做数据看板；
- 主图保留课堂规模和真实环境。

### 8.3 从首页进入作品

- 使用正常页面导航，不增加开场、确认页或角色过渡；
- 首页与作品页共享页头语言、蓝色链接和排版网格；
- Project 000 的背景从浅灰白自然变为稍暖的纸张色；
- 页面切换不依赖动画，必要时只使用 150–250ms 的内容显现。

## 9. 60 秒互动设计

### 9.1 学习目标

访客只需亲自感受到：答案是否可用，取决于 AI 是否知道需求、场景和约束。

### 9.2 状态流程

```text
模糊指令
  ↓ 点击“让 AI 回答”
正确但不可用的预置回答
  ↓ 点击“让它知道更多”
依次补充需求、场景、约束
  ↓
组合后的完整指令
  ↓ 点击“再回答一次”
前后对照与课程收束
```

### 9.3 模糊指令

标题：

> 为什么你问 AI，总得到一堆“正确的废话”？

演示指令：

> 把这些材料汇总一下。

结果判断：

> 每句话都没错，但你还是不知道它能不能拿去汇报。

必须持续显示“网页预置演示”，避免被误解为实时模型输出。

### 9.4 补充三个信息

三步一次只聚焦一个选择：

1. **需求**：一页汇报要点；
2. **场景**：给领导做周会汇报；
3. **约束**：领导很看重数据。

组合后的完整指令最终措辞在实现前与课程原始材料核对。

### 9.5 前后对照

桌面端左右对照，移动端上下堆叠。第二次答案明确突出：

- 关键数据与变化；
- 异常与原因；
- 需要领导决策的问题。

收束：

> AI 没有突然变聪明。它只是终于知道：你要什么、用在哪、最在意什么。

### 9.6 行为规则

- 每个状态只有一个主要动作；
- 允许返回上一步；
- 使用原生按钮，支持键盘和触摸；
- 结果更新对辅助技术可感知；
- 标签与颜色共同区分需求、场景和约束；
- 状态变化控制在 150–300ms；
- 开启减少动态效果后即时更新内容。

## 10. Project 000 长页节奏

项目页保持既定八层叙事，但不做成八张同样大小的卡片：

- 封面：真实课堂与核心问题；
- 互动：收紧阅读宽度，形成独立体验；
- 用户问题：工作词语与跟做照片；
- 研发过程：桌面式时间线、早期文档和协作证据；
- 210 分钟取舍：时间带与删减过程；
- 体验设计：不同形态的真实证据；
- 四地迭代：同一时间轴上的四次发布；
- 反思：效果、缺点和个人发现同时存在。

## 11. 动效原则

- MVP 动效只说明状态变化、阅读顺序和前后对照；
- 首页不使用漂浮装饰、粒子、视差或自动循环动画；
- 不拦截原生滚动；
- 交互反馈快速、可中断；
- 所有非必要动效响应 `prefers-reduced-motion`；
- 如果移除一个动效不会损失信息，就允许不做。

## 12. 素材优先级

首个可浏览切片优先使用：

1. 山西课堂远景作为 Project 000 主视觉；
2. 厦门跟做照片支持用户问题；
3. 四地授课时间节点手稿支持 210 分钟取舍；
4. 一张道具实物图或感言卡支持真实证据；
5. 《老赵的一天》短视频在完成隐私与体积检查后再决定是否进入首版。

素材完成隐私检查前，不进入公开资产目录。

## 13. 响应式规则

- 设计基准同时包含约 390px 手机和 1280px 桌面；
- 双栏内容在窄屏改为单列，不缩小文字硬塞；
- 前后对照、四地时间线和 210 分钟时间带在移动端改为纵向因果序列；
- 图片裁剪优先保留证据含义；
- 不使用横向滚动承载关键正文。

## 14. 首个可浏览切片验收标准

- 首页 10 秒内可理解姓名、能力方向和网站性质；
- Project 000 是首页最明确的下一步；
- 首页全程使用明亮背景，不依赖深色区域制造氛围；
- 页面不出现灵眠、静眠森或需要世界观知识的文案；
- Project 000 封面包含标题、问题、真实图片和四项事实；
- 60 秒互动从模糊答案走到前后对照；
- 桌面端和移动端无关键内容遮挡或溢出；
- 没有未经核对的原话、效果数据或敏感界面。

## 15. 待确认项

这些问题不阻挡当前版本：

1. 正式域名与首页社交分享信息；
2. 公众号二维码的真实设备扫描验收；
3. Project 000 文章数据“306 次阅读、64% 完读率”是否公开。
