# 首版架构说明

状态：MVP 已实现  
更新时间：2026-08-20

## 1. 架构判断

首版只需要一个应用：`apps/main`。

理由：

- 首页与 Project 000 共享同一站点身份、URL 和部署边界；
- Project 000 虽有独立视觉段落与一个互动，但仍是单页作品详情；
- 它没有独立多页面体系、特殊服务端能力或独立依赖；
- 不拆 App 是当前最简单、最易回退的实现。

## 2. 目录组织

```text
personal-site/
├── apps/
│   └── main/
│       ├── app/
│       │   ├── page.tsx
│       │   ├── works/
│       │   │   ├── project-000/
│       │   │   │   └── page.tsx
│       │   │   └── project-001/
│       │   │       └── page.tsx
│       │   ├── layout.tsx
│       │   └── globals.css
│       ├── components/
│       │   ├── site/
│       │   └── works/
│       │       ├── project-000/
│       │       └── project-001/
│       ├── content/
│       │   └── projects/
│       ├── styles/
│       │   └── projects/
│       └── public/
│           ├── profile/
│           │   └── wechat-official-account-qr.png
│           └── projects/
│               ├── project-000/
│               └── project-001/
├── docs/
└── README.md
```

目录含义如下：

- `app/` 是页面地址和路由入口；
- `components/` 是可以组合到页面中的界面部件；
- `content/` 是已经整理、核对并准备展示的网页内容；
- `styles/` 是作品专属的颜色、字体、间距和布局等视觉规则；当前全站样式入口仍是 `app/globals.css`；
- `public/` 是经过审核和处理后供网页发布的图片、视频和其他静态素材。

同一个 Project 可以同时出现在这些目录中，因为它们保存的是不同类型的文件。作品专属文件按作品归档，公共能力集中在 `components/site/` 和公共样式中；不复制公共组件到各个作品，也不因页面很长就拆成独立 App。

实际应用已建立在 `apps/main`。当前核心客户端边界仍是 `components/PromptExperience.tsx`，公共组件也仍位于 `components/` 根目录；后续新增或重构时，按本节约定分别归档到 `components/works/<project-id>/` 和 `components/site/`。其余页面内容保持为服务端组件。上述 `content/`、`styles/` 和未来作品目录按需创建，不要求现在批量建立空目录。

首版不实现灵眠、静眠森或“现实映像”等叙事层。相关设定保留在全站资料中，未来只有在作品数量和入口结构确实需要时才重新评估。

## 3. 技术基线

- TypeScript
- React
- Next.js App Router
- 一套全局样式与语义化组件
- Git
- Vercel

首版没有引入动画库、组件库、CMS、数据库或服务端 API。MVP 不存在拖拽或速度交接，因此使用 CSS 处理即时按压与非手势状态过渡；若未来出现可拖拽 Sheet、卡片或画廊，再评估支持速度连续性的弹簧方案。

## 4. 路由

```text
/                   首页
/works/project-000  Project 000 作品详情
```

首页到 Project 000 只需一次点击。Project 000 必须可以直接访问和独立分享，并提供清晰的返回首页入口。

## 5. 渲染与客户端边界

- 首页和 Project 000 的主体内容采用服务端渲染的静态内容。
- 仅“正确的废话”互动及必要的局部状态使用客户端组件。
- 预置回答作为本地结构化数据存在，不发送网络请求。
- 不在客户端包含秘密信息或原始内部资料。

## 6. 内容与资产

- 页面事实来自 Project 000 资料库，不在代码中重新创造一套事实来源。
- 经过筛选、裁剪、模糊和压缩的网页资产另存至项目 `public/`。
- 公众号二维码只保留用户提供截图中的二维码主体，原始微信页面不进入公开目录。
- 原始 PPT、Word、照片和视频保持只读，不复制整个原始资料目录。
- 每个发布资产需要保留来源记录与隐私处理状态。

## 7. SEO 与分享

- 首页元信息直接说明这是袁策书的个人产品实验室。
- Project 000 使用独立标题、简介和真实项目主图。
- 不让作品详情继承首页的通用分享文案或通用主图。
- 站点正式域名确认后再补齐 canonical、站点地图与绝对分享地址。

## 8. 部署与环境变量

首版为单一 Vercel Project，对应 `apps/main`。当前没有环境变量需求。

## 9. 影响范围

当前方案只影响新建的个人站代码仓库，不改动 `00_项目总说明` 和 `01_资料库` 中的原始资料。
