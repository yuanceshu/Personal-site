# 架构说明

状态：静眠森独立 App 与 AgentOS 已完成 Production 部署；Preview Agent 链路、WAF、Cron 和主站域名复核待完成
更新时间：2026-09-18

## 1. 架构判断

仓库采用一个 Git Repository。内容信息架构与技术架构分开维护；首页内容线和作品归类见[内容信息架构](product/00_内容信息架构.md)。

以下为当前技术部署结构；工作台开发状态另见文末及其实现文档。行业实验室和后端扩展规则见第 10 节，不把内容分类视为部署结构。

```text
personal-site/
├── apps/
│   ├── main/                    # 个人主站、Project 000
│   └── jingmiansen/             # 静眠森独立 Next.js App
├── services/
│   ├── experiment-agents/       # 实验作品共用 FastAPI 服务
│   └── jingmiansen-agents/      # 静眠森专属 Agno AgentOS / FastAPI
├── docs/
└── README.md
```

静眠森已经具备独立视觉、多页面、独立域名受众边界和独立服务端能力，因此从 `apps/main` 拆为 `apps/jingmiansen`。两个 Next App 不共享组件包、样式系统或运行时依赖；跨 App 使用普通整页跳转。Agent 服务仍只服务静眠森，不扩展为全站 AI 网关。

这次拆分解决的是普通访问路径上的发现边界，不是绝对匿名：主站入站链接、永久重定向、搜索引擎关系图和同一公开 Git 仓库仍可能被有意调查者关联。

静眠森：

```text

/xing-yue-xiang-hu   星月相护
/witch-train         菲莉卡与魔女列车
/rainy-night-cafe    雨夜啡庭
```

主站的 `/works/jingmiansen` 及三个旧子路径永久 308 到独立站短路径，早期 `/works/jingmiansen/rainy-night-cafe/xing-yue-xiang-hu` 也统一到 `/xing-yue-xiang-hu`。主站入口使用 `JINGMIANSEN_SITE_URL`，外链和旧址响应采用 `no-referrer`。静眠森内部只有短路径和世界内部导航，不渲染返回主站入口。

## 3. 渲染与客户端边界

- 四个静眠森页面主体继续静态生成；角色服务失败不影响作品浏览；
- 《星月相护》正文和图片由服务端渲染，客户端只负责章节、进度和双视角状态；
- `LiveCharacterDialogue` 负责输入、SSE、有限高滚动和匿名本地恢复；
- 每个浏览器生成一个随机 `visitorId`，每个角色拥有独立 `sessionId`；
- LocalStorage 保存每个角色最近 8 轮界面消息与更新时间，30 天无活动后丢弃；
- “新对话”立即轮换 session，清空本地记录，并经 Next.js `DELETE` 尽力删除服务端旧会话；
- 清除浏览器数据、无痕模式或更换设备视为新访客；不提供账号、跨设备同步或长期记忆。

## 4. 角色请求数据流

```text
浏览器
  → 静眠森 Web POST /api/jingmiansen/chat
  → Bearer Token
  → AgentOS POST /agents/{agentId}/runs
  → MiniMax OpenAI-compatible API（M2-her）

浏览器“新对话”
  → 静眠森 Web DELETE /api/jingmiansen/chat
  → Bearer Token
  → Agent 服务 DELETE /internal/sessions

Vercel Cron（每日）
  → CRON_SECRET
  → Agent 服务 GET /internal/cleanup
  → 删除连续 30 天未活动会话
```

Web API 只接受 `lingmian | felica | marina`、1—1200 字消息及格式合规的匿名 ID。Agent 只把最近 8 次运行加入模型上下文。浏览器不接触 MiniMax Key、Agent URL、数据库连接串或共享 Secret。

## 5. 存储

- 本地没有 `DATABASE_URL` 时使用 `data/jingmiansen.db`；
- Vercel 必须配置 Neon pooled `DATABASE_URL`，AgentOS 使用 `PostgresDb`；
- Production 与 Preview 使用不同 Neon 分支；
- Neon 与 Agent Function 均选择 Singapore，减少数据库往返；
- 数据库只连接 Agent Project，不连接主站或静眠森 Web；
- 数据库中的会话是有限上下文缓存，不是人物长期记忆或用户档案。

## 6. 安全与公开面

- AgentOS 原生接口、文档和内部会话删除接口由 `JINGMIANSEN_AGENT_TOKEN` 保护；
- `/healthz` 只返回 `{"status":"ok"}`；
- `/internal/cleanup` 只接受 Vercel `CRON_SECRET`；
- 生产配置缺少 Key、Postgres 或 Secret 时拒绝启动；
- 模型响应限制输出长度，请求超时 45 秒，最多重试 1 次；
- 应用错误不返回内部地址、模型名、角色列表、Key 或连接串；代码不记录消息正文和完整匿名 ID；
- 静眠森 Web Project 的 Vercel WAF 需对 `POST /api/jingmiansen/chat` 配置每 IP 每 10 分钟 20 次，第 21 次返回 429。

WAF 是账号侧配置，不由应用内存计数替代。Agent Project 不绑定公开自定义域名，其 Vercel URL 只提供给静眠森 Web 的服务端环境变量。

## 7. SEO 与发现边界

- Production 输出 canonical、`robots.txt` 和 `sitemap.xml`，允许正常收录；
- Preview 通过页面 robots 元数据和 `robots.txt` 禁止收录；
- 购买域名前使用 Vercel Production URL 作为 `JINGMIANSEN_SITE_URL`；
- 购买后将根域名写入 Production 环境变量并设为 canonical，`www` 在 Vercel 重定向到根域名；
- 静眠森 HTML、公开资源与角色提示词不得包含现实姓名、主站域名或可反推出主站身份的元数据。

## 8. Vercel Projects 与环境变量

| Project | Root Directory | 环境变量 |
|---|---|---|
| 主站 | `apps/main` | `JINGMIANSEN_SITE_URL` |
| 静眠森 Web | `apps/jingmiansen` | `JINGMIANSEN_SITE_URL`、`JINGMIANSEN_AGENT_URL`、`JINGMIANSEN_AGENT_TOKEN` |
| 静眠森 Agent | `services/jingmiansen-agents` | `MINIMAX_API_KEY`、`MINIMAX_BASE_URL`、`MINIMAX_MODEL`、`DATABASE_URL`、`JINGMIANSEN_AGENT_TOKEN`、`CRON_SECRET` |

Agent 可选调优变量：`MINIMAX_MAX_COMPLETION_TOKENS`、`MINIMAX_REQUEST_TIMEOUT`、`MINIMAX_MAX_RETRIES`。本地另用 `AGENT_DB_FILE`、`AGENT_OS_HOST` 和 `AGENT_OS_PORT`。

所有 Secret 只保存在本地忽略文件或 Vercel 加密环境变量中。Web 与 Agent 必须使用同一个随机 `JINGMIANSEN_AGENT_TOKEN`；不得提交 `.env`。

## 9. 发布顺序

1. 本地 lint、类型检查、测试和 production build；
2. 复核完整 Git 差异并推送；
3. 建立 Neon Singapore 项目及 Production/Preview 分支；
4. 部署 Agent Project，验证鉴权与健康检查；
5. 部署静眠森 Web Preview，验证三角色、会话恢复和新对话；
6. 配置 WAF 并验证第 21 次请求返回 429；
7. 发布静眠森 Production；
8. 最后发布主站入口和旧路径重定向。

原始 Word、PNG 与人物资料继续留在资料库。公开 App 只保存核对后的网页内容和压缩派生资产。

## 10. 实验作品扩展（已确认，按作品实施）

行业 AI 产品实验室作为主站作品集合，入口为 `/works/demos`，子作品为 `/works/demos/<demo-slug>`，行业先用标签表达。默认由 `apps/main` 承载前端；其他平级工具继续使用自己的作品路径。

实验作品有真实模型、工具或业务状态需求时使用 `services/experiment-agents`。FastAPI/Pydantic 承载 API 与契约；显式流程、Agno 和确定性业务模块按作品组织，共用部署不等于共享订单、上下文或工具权限。静眠森仍使用现有专属服务。

主站及内容页面静态优先；动态工具仍可由现有 Next.js 承载。已有 Vite H5 可保持独立应用，接入前评估迁移收益和维护边界。海汽原工程保持外部只读；公开版岛见在本仓库重新实现，尚未进入部署清单。

实验后端按执行时长、流式响应和状态需求选择函数或常驻部署。跨请求恢复和并发一致性也属于数据库需求，Mock 不豁免；公网访客隔离不能依赖客户端自报用户 ID。目录、平台选择条件和海汽接入边界见[实验作品组织与接入规划](06_实验作品组织与接入规划.md)。

工作台本地运行、接口与分层预算见 [实验服务说明](../services/experiment-agents/README.md)。主站新增服务端变量 `EXPERIMENT_AGENT_URL`、`EXPERIMENT_AGENT_TOKEN`；模型凭据只进入实验服务，不使用静眠森的部署或环境配置。

## 岛见（2026-09-14 本地交付）

集合与子作品仍属于 `apps/main`，新增一个专属 Next.js 代理和实验服务 `works/island_travel` 模块，不拆 App 或部署单元，不增加依赖。模型仅理解意图和完整行程条件；浏览器确定性生成演示班次、重新核算金额、校验库存和交易状态。

用户明确选择纯前端模拟交易：无跨访客共享订单、无跨请求业务恢复、刷新清空，因此不建立业务数据库；不沿用外部 JSON 订单存储。此例外不改变真实共享业务状态必须持久化的规则。

公网费用限制在主站代理中使用 Redis REST 原子窗口，每IP每600秒10次，主站新增服务端 `ISLAND_RATE_REDIS_URL`、`ISLAND_RATE_REDIS_TOKEN`、`ISLAND_RATE_SALT`。缺配置和计数失败均关闭真实模型调用。它是限流计数资源，不是业务数据库；上线资源配置、跨实例与第11次429仍待验收。完整请求预算、状态机和结果见[实现记录](projects/island-travel.md)。
