# 代码决策记录

## 2026-08-20 — 首版只建立 `apps/main`

**决定：** 首页与 Project 000 同属 `apps/main`，暂不建立其他 App。

**理由：** Project 000 是一个带单一互动的作品详情页，尚未达到独立世界的运行边界。

**影响：** 首版只有一个部署项目；未来新增独立世界时再增加 App。

---

## 2026-08-20 — Project 000 使用稳定路径 `/works/project-000`

**决定：** 项目编号作为首版 URL 标识，不以临时中文标题或课程名称生成路径。

**理由：** 路径短、稳定，并与项目资料中的编号一致。

**影响：** 页面标题与元信息仍使用对访客友好的正式中文名称。

---

## 2026-08-20 — 普通作品采用“公共能力集中、作品内容归档”的混合组织方式

**决定：** 主站普通作品继续共用 `apps/main`，但每个作品的路由、专属组件、网页内容、样式和发布素材按作品编号归档；网站公共组件和真正跨作品复用的样式集中管理。

**理由：** 这种组织方式既能让初学者从一个作品目录理解其组成，又能避免 Project 000、Project 001 之间互相污染或复制公共能力。作品本身不需要独立运行时、独立部署或独立依赖，因此不因文件数量增加而拆成新的 App。

**目录约定：**

- `app/works/project-000/`：作品路由入口；
- `components/works/project-000/`：作品专属界面和交互；
- `content/projects/project-000/`：已核对的网页内容，不放原始资料；
- `styles/projects/project-000/`：作品专属视觉规则；
- `public/projects/project-000/`：经过隐私检查和优化的发布素材；
- `components/site/` 与公共样式：跨作品共享能力。

**影响：** 未来只有在某个组件被多个作品稳定使用后，才将其提升到公共目录；作品专属目录按实际需要创建，不预先批量建立空目录。

---

## 2026-08-20 — 核心互动不接真实模型

**决定：** “正确的废话”互动只使用经过审核的预置前后答案。

**理由：** 互动目的是展示“需求 + 场景 + 约束”的课程方法，不是证明实时模型能力。

**影响：** 首版没有 API、密钥、费用、延迟和随机输出风险。

---

## 2026-08-20 — 首版不引入动画与 UI 组件依赖

**决定：** 基础视觉、布局和动效使用 CSS 与 React 原生能力实现。

**理由：** 当前核心动效数量少，尚未出现持续存在的复杂动画问题。

**影响：** 若实现阶段确认需要可中断的复杂空间转场，再单独记录依赖评估。

---

## 2026-08-20 — 主站与作品共享导航契约，不共享完整视觉

**状态：** 已被下一项决定替代，不再用于 MVP。

**决定：** 首页采用静眠森的深色梦境入口；Project 000 采用温暖、编辑化的现实纪录片视觉。

**理由：** 两者承担不同叙事职责。统一性来自返回入口、排版秩序和过渡语言，而不是强迫页面长得相同。

**影响：** 不预建覆盖所有页面的大型视觉组件库。

---

## 2026-08-20 — MVP 移除灵眠与静眠森，并采用明亮入口站

**决定：** 第一版首页不出现灵眠、静眠森、梦境入口或现实映像等设定。首页采用明亮、克制、以关键信息和作品入口为中心的编辑化设计。

**理由：** MVP 首先需要让访客快速理解创作者身份、核心能力和现有作品；世界观会增加额外理解成本。用户也明确不喜欢深色主视觉。

**影响：** 首页、导航、动效和 Project 000 的进入方式均使用普通信息语言；当前 V1 不预留灵眠或静眠森空入口。静眠森后续是否接入按独立创作世界重新判断。

---

## 2026-08-20 — MVP 使用 Apple Design 原则设计与开发

**决定：** 用户指定使用 `apple-design` 技能。MVP 采用系统字体、明亮材料、清晰空间关系、即时按压反馈、克制动效和完整的减少动态/透明度/高对比度适配。

**理由：** Apple 的核心价值在于目的、理解、反馈、空间一致性与精细工艺，适合本项目“小而完整”的质量目标。

**影响：** 不把页面做成 macOS 仿制品，不堆叠玻璃卡片；没有真实拖拽和速度交接的场景，因此不为“Apple 感”引入弹簧动画依赖。未来若新增手势驱动界面，再依据实时位置、速度和可中断性单独设计。

---

## 2026-08-20 — 第二版入口站采用第二人称欢迎

**决定：** 首页先问候、说明作者身份和个人信念，再引导访客进入作品；公众号作为唯一的持续关系出口。

**理由：** 首轮审查显示作品能力清晰，但作者本人和访客之间缺少关系入口。个人与专业平衡、偏个人诗意的口径能补足这一层，同时不牺牲案例页的证据感。

**影响：** 首页保留原有路由和单作品结构；Project 000 的互动压缩为一次补充信息，避免把预置演示误解成真实自由选择。

## 2026-08-20 — Project 000 从摘要式 MVP 升级为正式 V1

**决定：** 保留 `/works/project-000` 与 `apps/main` 边界，把 Project 000 扩展为约 5 分钟主叙事加可展开证据的正式案例。课程内容、作品组件、专属样式与发布素材分别归档到 `content/projects/project-000.ts`、`components/works/project-000/`、`styles/projects/project-000/` 和 `public/projects/project-000/`。

**理由：** 课程原始资料足以支撑比 MVP 摘要更完整的产品案例，但页面仍不需要独立运行时、视频播放器、后端或新依赖。分层阅读能同时服务快速浏览与深入核验。

**影响：** 页面公开三位核心协作者姓名，使用精确 210 分钟结构和四地版本日志；媒体采用经过筛选和隐私处理的静态图文。全页仍只有提示词体验是客户端组件，其余内容由服务端静态生成。

## 2026-08-21 — 静眠森调整为主站中的二级创作世界

**决定：** 主站继续由袁策书直接表达身份和全部作品入口；静眠森不作为主站入口的叙事外壳，而是未来与 Project 000 等入口同级的二级创作世界。灵眠只负责静眠森内部引路，轻小说、漫画等属于其内部第三级作品。

**理由：** 现实主站和二次元创作世界面对的内容与访客预期不同。分层后，主站保持直接清楚，静眠森也能拥有完整且不受现实作品牵制的世界观体验。

**影响：** 当前 V1 页面和路由不变，不创建静眠森 App 或占位入口。未来开发静眠森时，依据独立导航、多页面体系、视觉、依赖和部署边界重新决定 App 结构，并始终提供返回主站的入口。内容与设定以 `../../../01_资料库/资料_静眠森/` 为权威来源。

## 2026-08-21 — 桌面深色门厅实验

**决定：** 仅在主页宽度大于 `720px` 时启用深色数字展馆门厅；移动端继续使用既有明亮主页，Project 000 等子页面保持原样。本实验暂时例外于“MVP 使用明亮入口站”的视觉决定，不改写原基线。

**理由：** 需要验证深色空间、朦胧背景、单作品展品和环境式鼠标反馈能否形成更鲜明的个人入口，同时控制改动范围并保留完整回退路径。

**实现边界：** 不新增依赖、服务端能力或 WebGL 框架。背景图离线生成并压缩为 AVIF/JPEG，仅在桌面媒体查询中加载；动态层使用低分辨率 Canvas 流场纹理和 transform/opacity，粗指针、减少动态、失焦、页面隐藏或宽度不满足时停止循环并卸载动态监听。

**影响：** 首页增加独立桌面体验组件与作用域样式；现有 `SiteHeader`、移动端首页 DOM、共享组件和子页面视觉不变。实验结论确认前，不把这套视觉提升为全站规则。

**视觉校正（2026-08-21）：** 第一轮验收发现右侧暖光的静态对比高于鼠标反馈，且宽屏作品区右侧留白过大。因此沿用原展馆构图，对发布背景做离线局部压光与暖色高光压缩；桌面作品区改为向内容容器右端对齐，并将项目标题固定为两行。鼠标流场加入宽高比修正和低饱和冷蓝发光，但继续使用同一张背景纹理、四分之一分辨率流场和约 30fps 的空闲休眠机制。

## 2026-08-24 — 静眠森第一版继续使用 `apps/main`

**决定：** 静眠森使用 `/works/jingmiansen` 及三个显式子路由实现，暂不建立独立 App，也不修改当前首页。入口和概览页全部静态生成；共享内容数据、文章骨架与作用域样式只在静眠森作品目录内部复用。

**理由：** 静眠森已经拥有独立视觉和内部导航，但第一版仍没有独立运行时、依赖、服务端能力或部署需求。留在 `apps/main` 是更简单、可逆的选择，也能避免提前增加 Vercel 项目与跨 App 跳转配置。

**内容与署名：** 灵眠页只使用已确认人物设定；魔女列车页隐藏核心真相并匿名注明朋友提供世界设定；雨夜啡庭页注明《最终幻想 XIV》非官方二次创作背景。原始资料保持只读，网页内容在本地静态数据中维护。

**素材与交互：** 森林原始 PNG 不进入发布目录，只保存 AVIF 与 WebP 派生图。页面使用 CSS 完成克制玻璃材质、280ms Hover 与减少动态／透明度／高对比度适配，不增加动画或 UI 依赖。

## 2026-09-02 — 静眠森增加环境延续与本地预写角色对话

**决定：** 静眠森入口首屏继续使用既有森林场景；作品导航区使用同一层静态背景容器，随当前作品入口在冷雾森林、夜行列车和雨巷暖灯之间交叉淡化。三个子页面首屏分别使用与内容对应的静态场景图；灵眠和魔女列车页各增加一张已审核的透明背景人物立绘。

**角色入口：** 灵眠对话位于静眠森首屏，作为“进入森林”之外的可选入口；菲莉卡对话只出现在“菲莉卡与魔女列车”作品入口内部，不承担静眠森全局导航。两处对话均为两层预写话题树，访客可随时关闭或直接进入普通页面，不设置强制流程。

**稳定性边界：** 对话只使用 React 页面会话状态，刷新即重置；不使用真实 LLM、API、数据库、本地存储、打字延迟、声音、Canvas、WebGL 或新增第三方依赖。环境切换与面板出现仅改变 `opacity` 和 `transform`，约 200—240ms，并继续适配减少动态、减少透明度和高对比度偏好。所有路由仍在构建期静态预渲染。

**素材口径：** 新增场景图离线生成后压缩为 AVIF 与 WebP；人物立绘压缩为保留透明通道的 WebP。菲莉卡立绘依据用户确认已获公开使用授权的外观参考生成，仅采用金色双辫、猫耳、绿眼与绿／米／棕林地服装等外观特征，不复制参考截图中的界面、姿势或背景。发布素材只保留网页需要的派生文件，原图与授权参考归档在静眠森资料包。
