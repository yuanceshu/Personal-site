# 代码决策记录

## 2026-08-20 — 首版只建立 `apps/main`

**决定：** 首页与 Project 000 同属 `apps/main`，暂不建立其他 App。

**理由：** Project 000 是一个带单一互动的作品详情页，尚未达到独立世界的运行边界。

**影响：** 首版只有一个部署项目；未来新增独立世界时再增加 App。

## 2026-08-20 — Project 000 使用稳定路径 `/works/project-000`

**决定：** 项目编号作为首版 URL 标识，不以临时中文标题或课程名称生成路径。

**理由：** 路径短、稳定，并与项目资料中的编号一致。

**影响：** 页面标题与元信息仍使用对访客友好的正式中文名称。

## 2026-08-20 — 普通作品采用“公共能力集中、作品内容归档”的混合组织方式

**决定：** 主站普通作品继续共用 `apps/main`，但每个作品的路由、专属组件、网页内容、样式和发布素材按作品编号归档；网站公共组件和真正跨作品复用的样式集中管理。

**理由：** 这种组织方式既能让初学者从一个作品目录理解其组成，又能避免 Project 000、Project 001 之间互相污染或复制公共能力。作品本身不需要独立运行时、独立部署或独立依赖，因此不因文件数量增加而拆成新的 App。

**目录约定：**

- `app/works/project-000/`：作品路由入口；
- `components/works/project-000/`：作品专属界面和交互；
- `content/projects/project-000/`：已核对的网页内容，不放原始资料；
- `styles/projects/project-000/`：作品专属视觉规则；
- `public/projects/project-000/`：经过隐私检查和优化的发布素材；
- `components/site/` 与公共样式：跨作品共享能力。

**影响：** 未来只有在某个组件被多个作品稳定使用后，才将其提升到公共目录；作品专属目录按实际需要创建，不预先批量建立空目录。

## 2026-08-20 — MVP 移除灵眠与静眠森，并采用明亮入口站

**决定：** 第一版首页不出现灵眠、静眠森、梦境入口或现实映像等设定。首页采用明亮、克制、以关键信息和作品入口为中心的编辑化设计。

**理由：** MVP 首先需要让访客快速理解创作者身份、核心能力和现有作品；世界观会增加额外理解成本。用户也明确不喜欢深色主视觉。

**影响：** 首页、导航、动效和 Project 000 的进入方式均使用普通信息语言；当前 V1 不预留灵眠或静眠森空入口。静眠森后续是否接入按独立创作世界重新判断。

## 2026-08-20 — MVP 使用 Apple Design 原则设计与开发

**决定：** 用户指定使用 `apple-design` 技能。MVP 采用系统字体、明亮材料、清晰空间关系、即时按压反馈、克制动效和完整的减少动态/透明度/高对比度适配。

**理由：** Apple 的核心价值在于目的、理解、反馈、空间一致性与精细工艺，适合本项目“小而完整”的质量目标。

**影响：** 不把页面做成 macOS 仿制品，不堆叠玻璃卡片；没有真实拖拽和速度交接的场景，因此不为“Apple 感”引入弹簧动画依赖。未来若新增手势驱动界面，再依据实时位置、速度和可中断性单独设计。

## 2026-08-21 — 桌面深色门厅实验

**决定：** 仅在主页宽度大于 `720px` 时启用深色数字展馆门厅；移动端继续使用既有明亮主页，Project 000 等子页面保持原样。本实验暂时例外于“MVP 使用明亮入口站”的视觉决定，不改写原基线。

**理由：** 需要验证深色空间、朦胧背景、单作品展品和环境式鼠标反馈能否形成更鲜明的个人入口，同时控制改动范围并保留完整回退路径。

**实现边界：** 不新增依赖、服务端能力或 WebGL 框架。背景图离线生成并压缩为 AVIF/JPEG，仅在桌面媒体查询中加载；动态层使用低分辨率 Canvas 流场纹理和 transform/opacity，粗指针、减少动态、失焦、页面隐藏或宽度不满足时停止循环并卸载动态监听。

**影响：** 首页增加独立桌面体验组件与作用域样式；现有 `SiteHeader`、移动端首页 DOM、共享组件和子页面视觉不变。实验结论确认前，不把这套视觉提升为全站规则。

**视觉校正（2026-08-21）：** 第一轮验收发现右侧暖光的静态对比高于鼠标反馈，且宽屏作品区右侧留白过大。因此沿用原展馆构图，对发布背景做离线局部压光与暖色高光压缩；桌面作品区改为向内容容器右端对齐，并将项目标题固定为两行。鼠标流场加入宽高比修正和低饱和冷蓝发光，但继续使用同一张背景纹理、四分之一分辨率流场和约 30fps 的空闲休眠机制。

## 2026-09-03 — 静眠森采用独立域名映射与 Agno 实时角色服务

**决定：** 静眠森继续使用 `apps/main` 的现有页面和主站路径，同时允许一个或多个独立域名通过 `proxy.ts` 映射到同一套代码。独立域名只放行静眠森的短路径、静态素材和角色聊天 API；页面不显示返回主站链接，并设置 `noindex, nofollow, noarchive`。这是一种受众和发现边界，不是鉴权；已经知道主站域名的人仍可主动访问主站。本决定局部替代 2026-08-21 中“始终提供返回主站入口”的规则，仅针对独立域名上下文；从主站路径进入时仍可使用浏览器返回主站。

**决定：** 静眠森角色对话从预写话题树扩展为可选的真实模型自由对话。新增 `services/jingmiansen-agents` Python 服务，使用 Agno AgentOS 注册灵眠与菲莉卡两个 Agent，使用 MiniMax OpenAI-compatible API 的 `M2-her` 模型。Next.js 的 `/api/jingmiansen/chat` 只负责校验参数、代理 SSE 和隐藏服务地址细节，浏览器不接触 API Key。

**会话与资料边界：** 服务使用本地 SQLite 保存每个会话的有限历史，以支持多轮上下文；不启用 Agentic Memory、知识库、工具或 Team。运行时提示词只来自已经核对、允许公开的静眠森资料；不加载主站身份、私密资料、原始档案或未确认设定。

**API Key：** 本地填写在 `services/jingmiansen-agents/.env` 的 `MINIMAX_API_KEY`；该文件不提交 Git。主站仅在 `apps/main/.env.local` 配置 `JINGMIANSEN_AGENT_URL` 和 `JINGMIANSEN_STANDALONE_HOSTS`。

**替代方案与理由：** 没有复制第二套前端代码，也没有把 Agno 抽成全站 AI 网关；这样保留单一页面维护入口，同时只为真实的 Python Agent 运行时增加一个边界清晰的服务。

## 2026-09-04 — 《星月相护》使用服务端长文与最小客户端增强

## 2026-09-04 — Logo 改用规范图精确裁切位图

**后续：** 如果取得原始 SVG、AI、PDF 或 Figma 文件，再以原始矢量替换这些发布资产；在此之前不把人工描摹版本作为正式 Logo 使用。

## 2026-09-08 — 静眠森拆为独立 App 并为 AgentOS 增加生产边界

**替代范围：** 本决定保留此前实现历史，但替代“静眠森继续位于 `apps/main`、由 Host 映射、独立域名不收录、刷新后清空会话、生产只用 SQLite”的现状。Project 000 仍属于主站，不受影响。

**App 与关系：** 静眠森页面、内容、样式和素材迁入 `apps/jingmiansen`，与 `apps/main`、`services/jingmiansen-agents` 形成单仓库三个部署单元。静眠森只使用四个短路由；主站保留由 `JINGMIANSEN_SITE_URL` 驱动的单向入口和旧地址 308，外链不发送 Referer。静眠森不渲染主站入口。该设计是发现边界，不是绝对匿名或访问控制。

**SEO：** 静眠森 Production 允许搜索收录，输出 canonical、robots 和 sitemap；Preview 禁止收录。域名购买前使用 Vercel Production URL，购买后根域名成为 canonical，`www` 重定向到根域名。

**匿名会话：** 浏览器保存一个随机 `visitorId`、三个角色各自的 `sessionId`、最近 8 轮界面消息和更新时间。刷新恢复；清除浏览器数据、无痕模式或换设备视为新访客。“新对话”轮换 session 并尽力删除服务端旧会话。上下文只取最近 8 次运行，服务端和本地均按 30 天无活动过期，不引入账号、跨设备同步或长期记忆。

**生产存储与安全：** 本地继续使用 SQLite；Vercel 使用 Neon Singapore pooled Postgres，Production 与 Preview 分支隔离。AgentOS 原生接口使用共享 Bearer Secret，`/healthz` 只返回状态，清理 Cron 使用独立 `CRON_SECRET`。模型设置有限输出、45 秒超时和 1 次重试；Function 上限 60 秒。静眠森 Web 的 Vercel WAF 对聊天 POST 按 IP 每 10 分钟限制 20 次。Secret 不进入 Git、客户端或日志。

**未选择：** 不引入 Turborepo、共享组件包、账号系统、通用 AI 网关、全站数据库、知识库、工具、Team 或 Agentic Memory。
