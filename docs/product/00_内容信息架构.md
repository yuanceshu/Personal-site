# 内容信息架构

更新时间：2026-09-18

Read when：改变首页内容分类、作品策展关系、展示名或 catalog metadata 语义。

Do not read when：只改样式、技术边界、部署或单个作品内部行为。

Source of truth：本文档负责访客视角的内容分类；作品的精确 metadata 以 `apps/main/content/projects/catalog.ts` 为准，技术边界以架构文档为准。

本文只定义访客如何理解和浏览作品，不定义代码目录、App 数量、部署单元或后端服务归属。技术边界见[架构说明](../00_架构说明.md)；作品的实现范围见 `docs/projects/` 下对应文档。

## 分类的目的

这五条内容线是面向访客的策展关系，不是把每个项目变成一个一级栏目。它们共同回答一个问题：我如何把 AI 带进真实行业、带进学习与教学、带进产品和界面实验，也带进个人想象与创造，并把一路上的判断记录下来。AI 是共同媒介，不是需要被单独宣传的产品类别。

因此首页采用“4 + 1”的权重：前四条是主要作品线，最后的“AI 思记”是较轻的内容型尾声。2026-09-18 定稿的浏览顺序为：行业实践 → 产品 / 设计实验 → 个人创作 → 教学实践，最后回到思考记录——以最能直接证明能力的外部实践开场，以个人创作与授课收束。未来新增作品应先判断它属于哪一种实践、在这条叙事中的位置，以及是否已经有足够真实的内容；不为了填充分类而创建空占位或机械的同款区块。

首页标题中的连接符也属于信息架构的一部分：`+` 暗示 AI 进入行业，`与`强调教学关系，`×`强调碰撞和实验，`&`强调共同创造，而“AI 思记”不加连接符以保持安静和内化。视觉实现中应保持这些差异，并以统一的字体比例和排版系统维持整体归属。完整的首屏气质、标题层级与内容骨架见[首页内容线与晨光首屏](../07_首页内容线与晨光首屏.md)。

## 首页内容线

```text
AI + 行业
└── 行业 Demo 集
    ├── 岛见
    └── 食智助手

AI × 实验
├── AI 工作台（首页展示名「原型工作台」）
├── UI 实验室
└── 小麦子的生活漫画（首页展示名「亲子漫画」）

AI & 创造
└── 静眠森

AI 与授课
└── Project 000

AI 思记
└── 思考与持续关系出口（/thoughts 精选板块页 + 公众号入口，不作为作品实体）
```

## 三层关系

1. 内容分类：首页的五条内容线，是面向访客的策展和叙事关系。
2. 作品实体：Project 000、AI 工作台、UI 实验室、岛见、食智助手、静眠森等稳定对象。
3. 技术运行边界：`apps/main`、`apps/jingmiansen`、`services/experiment-agents` 和 `services/jingmiansen-agents`。

内容分类可以变化，但不应因此搬迁作品代码或修改作品 URL。作品实体可以在首页分类之间调整；App 和 Service 只在真实运行边界发生变化时调整。

## 作品 metadata

主站当前作品的内容层 metadata 维护在 `apps/main/content/projects/catalog.ts`。它负责记录稳定 ID、展示标题、首页分类、父级集合和入口类型，不负责描述组件、模型调用、数据库或部署。

`AI 思记`（2026-09-18 更新）已落地为 `/thoughts` 静态精选板块页：公众号「小袁AI感雾」介绍与关注引导 + 精选文章外链卡片（跳转公众号原文），不做站内全文与博客系统。它是主站内的独立板块，不是作品实体，因此不进入 `catalog.ts` 的作品注册中心；首页 `#thoughts` 尾声区保留公众号卡片并新增指向 `/thoughts` 的精选入口卡片。若未来出现真实的站内文章作品，再评估是否增加对应 metadata 和路由。
