# Project 000：课程作为产品案例

状态：正式 V1 已实现  
更新时间：2026-08-20

## 1. 实现定位

Project 000 是主站中的一个长篇作品详情页，不是独立 App、课程报名页、企业宣传页或通用提示词工具。

页面主命题在正式 V1 中调整为更符合事实边界的表达：

> 如何让一群 AI 基础不同的普通员工，在三个半小时后，真的愿意把 AI 用进明天的工作？

## 2. 页面范围

- 路由：`/works/project-000`
- 形态：单页纵向长叙事
- 强交互：一个约 60 秒的“正确的废话”预置体验
- 阅读模式：约 5 分钟主叙事，来源与过程证据按需展开
- 媒体：全静态图文，不发布原始 PPT 或内嵌视频
- 数据：本地静态内容
- 服务端：无 API、无数据库、无模型调用
- 导航：顶部与结尾均可返回个人作品首页，不使用世界观转场或角色引导

## 3. 内容结构

实现必须保持以下连续因果：

```text
核心问题
→ 亲自遇到正确的废话
→ 为什么普通员工会卡住
→ 如何组织研发与协作
→ 210 分钟如何取舍
→ 如何设计课堂体验
→ 四地如何连续迭代
→ 什么有效、什么仍然不够好
```

详细文案草案、素材建议和事实来源以：

`../../../../01_资料库/资料_AI课程设计展示/01_项目文档/03_网站内容与结构设计说明.md`

为准。

## 4. 互动边界

- 只展示“需求 + 场景 + 约束”；
- 前后答案均为网页演示预置内容；
- 不允许自由上传材料；
- 不接聊天界面；
- 不宣称量化提升；
- 完成后必须把体验连接回真实课程，而不是引导访客继续生成提示词。

## 5. 正式 V1 关键判断

页面至少要让访客看见：

1. 换对协作者，而不是维持省事但低质量的原安排；
2. 保护文字类真实工作主干，主动削减不稳定或次要内容；
3. 在 210 分钟限制下宁可删内容，也保留互动与行为转化；
4. 四场课程不是重复播放，而是连续发布和迭代；
5. 作者不擅长即兴，使用逐字稿、试讲和准备来发挥自己的优势；
6. 课程有效，但互动点评与任务化仍然有明确不足。

## 6. 事实来源

实现前必须直接核对：

- `AI提效实战三讲 V1.5 - 词.pptx`
- `AI工具提效培训课程大纲及分工 V0.2.docx`
- `让AI进入真实工作：四场《AI提效实战三讲》的观察、复盘与思考-袁策书.docx`
- 四地授课时间节点手写记录
- 页面实际采用的每张照片、感言卡、道具和视频

项目内容蓝图已经确认可公开：

- 4 座城市；
- 339 名学员；
- 约 160 小时研发投入；
- 单场 3.5 小时 / 210 分钟；
- 四地日期与人数。

文章数据“306 次阅读、64% 完读率”发布前再次确认。

## 7. 隐私与素材处理

- 公司名称和 Logo 可保留；
- 现场人物可公开，但优先远景和群体照片；
- 内部工具界面必须模糊；
- 感言卡隐藏姓名；
- 检查外部工具头像、历史对话、文件名和账号信息；
- 检查视频画面、字幕、声音、通知和账号；
- 处理后的网页资产另存，绝不覆盖原件；
- 手机号与二维码不成为视觉中心。

## 8. 发布资产清单格式

实现阶段为每项素材记录：

```text
网页文件名：
原始来源：
用于段落：
裁剪说明：
隐私处理：
文字/事实核对：
最终尺寸与格式：
```

## 9. 作品级完成标准

- 首屏 10 秒内可理解核心问题；
- 60 秒互动可以完整完成；
- 至少展示三次重要判断与取舍；
- 四地形成迭代线；
- 至少使用一种研发证据、课堂证据与反馈证据；
- 数字、原话和素材可追溯；
- 结尾同时存在效果、不足和个人发现；
- 移动端完整可用，动效不妨碍阅读。
