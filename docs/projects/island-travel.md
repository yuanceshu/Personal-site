## 行为与接口

- 使用真实海南城市名；品牌、班次、价格、余票、乘客、支付和车票均为虚构演示。
- 页面状态保存在岛见布局的浏览器内存；内部导航和前进后退保留当前流程，刷新清空。没有 localStorage、sessionStorage 或业务数据库。
- 默认真实 AI 只负责自然语言意图理解。班次、金额、库存、FAQ、订单和支付状态由确定性演示代码生成。
- `POST /api/experiments/island-travel/chat` 代理 `POST /works/island-travel/chat`；输入包含 message、conditions 和最多 16 条 history，输出包含 mode、intent、conditions、reply、faq、selection。
- Pydantic 是权威契约，前端 Zod 校验。乘客表单不发送给模型，自由文本中的长数字和家庭住址提示词拒绝发送；门到门规划只选预设公共地点。
- 缺项按出发地、目的地、日期补问；日期按上海时区解释。新行程重置当前对话和选择，但保留本页订单；刷新清空全部。
- 创建订单必须明确确认。支付失败可重试原订单；支付未知只能查单；出票异常只重试出票，不重复支付。
- 一级导航为“选择行程 / 我的行程 / 我的订单”。“我的行程”从已出票订单派生；已退款订单保留取消记录，不保留有效乘车凭证。班次、人数和金额只以订单为事实源。
- 乘车凭证为清晰标注“DEMO / 不可乘车”的演示图形，不包含可扫描码。演示检票、发车、到达由访客依次确认，不能跳步或倒退，和真实时钟、车辆动态无关。只有已出票订单可推进。
- 仅已出票且处于待出发阶段的车票可退。演示手续费固定为订单金额的 10%，所有试算使用整数分。试算绑定订单版本，提交时重新核对资格与金额；取消与失败不改订单。成功后订单已退款、凭证失效、行程取消、释放对应座位；重复提交不重复释放。
- 真实 AI 与规则演示模式都能识别“退票/退款”为 `request_refund`，只引导至订单和结构化退票页；多笔订单必须由用户自行选择。模型请求与响应不包含订单编号、金额、个人资料或退款结果。
- 改签仅用于已出票、待出发且未退款的订单；路线与人数不变，目标只能是未来七天内的其他可售班次。报价绑定订单版本、原班次、目标班次及整数分差价；确认和完成时重新核验资格、目标余票及价格。
- 补差价进入同订单的演示支付状态，支持成功、失败重试、结果未知后主动查单；未知状态不能取消或重付。退差价、零差价明确选择成功或失败。完成前原票有效，但演示检票、退款、再次改签和开票暂停；成功后原班次释放、新班次占用、订单和行程一次性切换。目标售罄时不改变原票，查单可结束该次未完成改签。
- 订单记录初始票价、每次成功改签的原/新班次和差价、退票金额及开票记录；累计模拟支付、退回与净额由记录按整数分计算。待支付、支付失败及结果未知的初始金额不计入已确认支付。退票按改签后的当前金额试算。
- 演示开票仅用于已出票、未退款且无进行中改签的订单。只提供“演示个人抬头”和“岛见演示公司”，不输入税号、姓名或联系人；每个票价版本仅一份有效页面记录。改签成功或退款后旧记录自动显示为作废，可针对更新后的有效票价重新申请。
- 订单详情集中提供凭证、退票、改签、开票入口和不可用原因，并展示操作及金额历史。订单列表“售后”筛选包含有退票或改签成功记录、或改签进行中的订单。
- 真实 AI 与规则模式还支持 `request_reschedule`、`request_invoice`，只引导用户选订单和进入本地页面；模型不接收订单编号、金额、个人资料或交易结果，也不能执行售后或开票。
- 规划页发现车站接驳、景区直通车和包车，不增加一级导航。交通服务使用小规模虚构本地目录和未来七天日期；接驳、直通车按人计价，包车按车计价并限制乘坐人数。产品价格、时间、容量和余量均由本地代码决定，提交前重新核验。
- 交通产品独立核对与明确确认，联系人仅为预设虚构旅客；订单编号使用 `DP-`，与车票 `DJ-` 一同显示在订单列表，可按车票/交通产品筛选。产品支付支持成功、失败重试和未知后主动查单；成功后是“服务待使用”而不是出票，手动确认才能模拟完成。产品退票、改签和开票本批不开放，车票服务页不应用于产品。
- 从车票行程详情可安排衔接的抵达接驳。关联产品保存来源车票编号、班次和票价版本；车票退款或改签后，车票与产品详情提示重新检查，不自动退款、调整或替换产品订单。
- 规划页的门到门方案仅使用预设公共地点、固定演示时长和当前可售车票/产品，不输入家庭地址，也不调用地图或路线服务。前后段按顺序衔接且每次换乘至少 30 分钟；无可行组合时说明调整条件。方案展示分段时间、等待、各段价与当前合计，各段分别核对、下单、结算，没有一键购买。
- 门到门草稿在本次浏览器会话中保留分段预订键，已预订段不重复下单；待支付车票显示已预订但产品段需等出票后再下单。车票退款或改签、目标产品售罄会将相关段标为需重新检查，并把合计明确改标为原草稿估价；不自动购买替代品。刷新清空草稿和订单。
- 真实 AI 和规则模式增加 `request_product`、`request_door_plan`；仅保留明确提到的预设公共地点与需求条件，前端按用户描述匹配本地产品目录或生成本地门到门方案，不从模型接受价格、库存或路线。
- 订单详情（含 `DP-` 产品单）与车票行程详情可进入客服工单；类别限失物招领、投诉建议、人工协助、无障碍协助。使用固定虚构联系人和 1–500 字描述，输入和提交时拦截明显手机号、证件号码及住址提示。描述仅在浏览器内存中，不发送模型、不落库；提交前独立核对确认，`DS-` 编号及确认键保证同一次确认不重复创建。工单按“模拟已提交 → 模拟处理中 → 模拟已完成”手动确认推进，各类别给出明确演示结果。人工协助不代表接通真实客服。
- 已出票、待出发的车票可在行程详情开启或关闭出发提醒偏好，预计时间按当前班次计划发车前 2 小时推算，仅作页面展示；不设定时器，不发送系统通知、短信或邮件。改签成功后同一开关按新班次重算预计时间，退款和模拟检票后撤销；刷新全部清空。
- 真实 AI 与规则模式增加 `request_support`、`request_reminder`。模型只理解意图；任何对话消息都不会提交工单、切换提醒或执行交易。订单/行程详情的对话入口显式绑定当前订单；消息明确提到单个现有 `DJ-`/`DP-` 编号时优先定位，多个或无法定位时要求用户选单。客服类消息发送给模型前替换为不含工单描述的固定意图短句；订单编号从模型请求与历史中剔除，业务资格仍由本地代码判断。

## 限流与公开边界

真实模型调用由主站使用 Upstash-compatible Redis REST 原子滑动窗口限流：每个可信客户端 IP 每 600 秒 10 次。只存环境隔离的 HMAC IP 摘要、随机请求编号和时间戳，600 秒过期；不存聊天或乘客信息。

生产只信任部署平台覆写的客户端 IP 头。缺少 `ISLAND_RATE_REDIS_URL`、`ISLAND_RATE_REDIS_TOKEN`、`ISLAND_RATE_SALT` 或计数失败时返回 503，关闭真实调用；仅非生产 localhost 可使用内存计数。

## 发布前验收

当前本地单元、浏览器、主站构建、实验服务测试和少量真实模型链路已经通过，但不等于公网限流完成。发布前必须：

1. 配置真实 Redis REST 资源并验证跨实例第 11 次请求返回 429、10 分钟后恢复。
2. 先部署实验服务，再验证主站 Preview 的凭据、HTTPS、真实模型、超时和失败恢复。
3. 复核真实手机、公开素材和全部订单异常路径后再发布 Production。
